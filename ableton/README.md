# ADEHack — Live 10 Remote Script (TCP 127.0.0.1:9004, newline-delimited JSON)

Install: `./ableton/install.sh`, restart Live, Preferences > Link/MIDI > Control Surface > "ADEHack" (In/Out: None).
Test: `printf '{"cmd":"ping"}\n' | nc 127.0.0.1 9004` (or `node ableton/client.js ping`). Log: `~/Library/Preferences/Ableton/Live 10.*/Log.txt` (grep ADEHack).

Commands: `version` -> {ok, version, cmds:[...]} (also in `ping`; ableton/VERSION holds the same string), `ping`, `set_tempo {bpm}`, `list_tracks`, `select_track {track:int|name}`, `create_midi_track {name?, index=-1}`,
`create_clip {track:"selected"|int|name, slot?, length, notes|pattern, mapping, singleNote, name?, fire?, overwrite?}` (no slot = first empty slot, or a new scene when all are full; a slot holding a clip whose name differs from `name` replies ok:false unless overwrite:true — our clips are named after their layer so re-pushing a layer updates in place via `select_all_notes()+replace_selected_notes()` and a playing clip
stays in sync; an empty notes list wipes the clip with `remove_notes`; pass recreate:true to delete+create instead; velocities clamp to 1..127; fire is skipped if the slot is already playing; then focuses it like focus_clip unless show:false),
`load_sample {path, track?:int|name, mode:"replace"|"append"}` (resolves the target track once and re-selects it before every load so a retry cannot land on a track the user clicked meanwhile; replace = hot-swap the track's existing
Simpler via `browser.hotswap_target = device` so `load_item` swaps the sample instead of adding a second Simpler, falling back to `track.delete_device`; a non-Simpler instrument (Drum Rack, Impulse, ...) is never replaced: ok:false telling you to use mode "append" or a new track; re-scans browser roots user_folders > current_project > user_library > samples
every ~0.3 s for up to ~2.4 s via schedule_message before replying not found — freshly written wavs take a moment to index; use a client timeout >= 5 s),
`focus_clip {track, slot?}` (highlight slot, detail_clip, Session + Detail/Clip views, clip.view.show_loop()),
`arrangement_record {bars?} | {scenes:[{index,bars},...]} | {stop:true}`, all with optional `at:"end"|"start"|"current"|<beats>` (default "end" = next bar after song.last_event_time so layouts append — the playhead is used only with at:"current"; reply adds at_beats, from_bar; song.loop and count_in_duration are switched off for the take and restored afterwards, back_to_arranger is cleared, pending play_for stops are cancelled, and the playhead is parked at the end), `arrangement_info {}` -> {ok, last_event_time, bars, beats_per_bar, current_song_time, loop, is_playing} (record_mode on; scenes form fires each scene in turn for its bars (next fire ~0.2 s early so launch quantization lands it on the bar), then stops record + transport and shows the Arranger; a new call cancels the running sequence), `clip_edit {track, slot, quantize?:{grid:0..8 (5 = 1/16), amount:0..1}, duplicate_loop?, crop?, loop_start?, loop_end?, color_index?, name?}` -> {ok, done:[ops], errors:{op:msg}, clip:{name,length,loop_start,loop_end,color_index,is_playing}},
`duplicate_clip {track, slot, to_slot}`, `duplicate_scene {index}` -> {ok,index,new_index,name}, `duplicate_track {track, name?}` -> {ok,source_index,index,name}, `rename_scene {index,name}`,
`transport_setup {metronome?, loop?, loop_start?, loop_length?, launch_quantization?:int (Live.Song.Quantization: 4 = 1 bar), swing?:0..1, tempo?, tempo_ramp?:{to, seconds}}` -> {ok, done, errors, state:{tempo,is_playing,metronome,loop,loop_start,loop_length,swing_amount,clip_trigger_quantization,can_capture_midi,tempo_ramp?}} (ramp steps every 100 ms; a new ramp cancels the old),
`capture_midi {}` (ok:false when !song.can_capture_midi), `set_track_color {track, color_index}`; list_tracks entries also carry color_index, is_grouped, group_track, fold_state.
`show_view {view:"Session"|"Arranger"|"Detail/Clip"|"Detail/DeviceChain"}`, `play`, `stop`,
`list_devices {track, params?:true}` (params: first 32 of each device with value/min/max/display),
`load_device {track, name}` (BFS over browser.audio_effects > instruments > midi_effects > drums > sounds, exact then case-insensitive;
selects the track, `load_item` appends the device; replies the new device + params), `set_device_param {track, device:int|name, param:int|name, value}` (clamped),
`delete_device {track, device}`, `set_mixer {track, volume?:0..1 (0.85 = 0 dB), pan?:-1..1, mute?, solo?, arm?}`,
`create_scene {index=-1, name?}`, `fire_scene {index}`, `list_scenes`, `stop_clip {track, slot}`, `delete_track {track}`, `rename_track {track,name}`,
`load_to_pad {track, note:0..127, path, name?}` -> {ok, track, note, route:"pad_hotswap"|"plain_load_item", device_index, rack_created, pad:{note,name,has_chain,chain_name,chain_devices,sample,mute,solo}, devices_appended_to_track, observed:[steps], item} (loads a Drum Rack first if the track has none; Push's PadHotswapping route: select rack + pad, browser.hotswap_target = pad, load_item; ok:false with the observed state if the sample did not land in the pad), `pad_info {track, device?, all?}` -> {ok, track, device_index, device, pad_count, pads:[{note,name,has_chain,chain_name,chain_devices,sample,mute,solo}]} (pads with chains unless all:true),
`describe_set {}` -> {ok, version, tempo, is_playing, loop:{on,start,length}, signature, current_song_time, scenes, selected_scene, selected_track, tracks:[{index,name,is_midi,selected,color_index,is_group,group_track,mixer:{volume,pan,mute,solo,arm,sends},devices:[{index,name,class_name,type,is_active,sample?}],has_sound,clips:[{slot,name,length,is_playing,is_triggered,looping,color_index,is_audio,note_count,notes_preview(16)|file_path,warping,gain}]}], returns, master:{volume}, transport} (first 16 clips per track),
`get_clip_notes {track, slot}` -> {ok, track, slot, name, length, note_count, truncated, notes:[{pitch,start,duration,velocity,mute}]} (cap 2000; Live 10 Clip.get_notes(from_time, from_pitch, time_span, pitch_span)),
`play_for {seconds}` / `play_scene_for {index, seconds}` -> {ok, stops_in_seconds, scene?} (schedule_message stop at seconds+0.3; a new call, `play`, `stop` or `arrangement_record` cancels the pending stop, and a timed stop never fires while record_mode is on),
`set_simpler {track, device?, mode?:classic|oneshot|slice, warp?:bool, warp_mode?:beats|tones|texture|repitch|complex|complex_pro, loop?:bool ('S Loop On' param), gain_db?, voices?:1..32, retrigger?:bool, start_marker?, end_marker? (sample frames)}` -> {ok, track, device, done:[...], errors:{...}, state}, `sample_info {track, device?}` -> {ok, track, device, sample:{playback_mode (0 classic/1 one-shot/2 slicing), voices, retrigger, file_path, length (frames), warping, warp_mode, gain, start_marker, end_marker, slices, loop}},
`set_send {track, send:'A'|'B'|int|name, level?:0..1}` -> {ok, track, sends:[{index,name,level}]},
`browse {root:instruments|sounds|drums|audio_effects|midi_effects|user_folders|..., query?, depth=2, limit=200}` -> {ok, root, items:[{name,is_folder,is_loadable,is_device,path:[...]}], truncated},
load_device matching: exact device > exact preset > alias (Ping Pong Delay/Simple Delay/Echo -> Delay, eq -> EQ Eight, glue -> Glue Compressor, ...) > case-insensitive > substring; reply has match + requested; not-found lists the real top-level names.
Live 10 Standard here has NO Echo / Ping Pong Delay / Operator / Analog / Wavetable (Suite); instruments = Drum Rack, Impulse, Instrument Rack, Simpler, External Instrument; presets live under `sounds` (Bass, Pad, Synth Lead, ...).
`browse {root?}` (legacy debug: top-level names under each browser root).

v5.7 additions: `undo {steps=1}` -> {ok, undone, requested, can_undo, can_redo} / `redo {steps=1}` -> {ok, redone, ...} (Song.undo()/redo() while can_undo/can_redo),
`clip_info {track, slot}` -> {ok, track, slot, name, is_audio_clip, length, looping, loop_start, loop_end, start_marker, end_marker, color_index, is_playing, is_recording, + audio: file_path, warping, warp_mode (name), pitch_coarse, pitch_fine, gain, gain_display_string | midi: note_count},
`set_clip_warp {track, slot, warp?:bool, warp_mode?:beats|tones|texture|repitch|complex|complex_pro, pitch_coarse?:-48..48, pitch_fine?:-50..50, gain?:0..1, looping?}` -> {ok, track, slot, done, errors, clip} (audio clips only; Live.Clip.WarpMode is resolved via getattr, a missing enum gives a clear error),
`load_audio_clip {track, slot=0, name|path, warp=true, warp_mode="complex_pro" (falls back to complex), looping=true, clip_name?, fire?, overwrite?, show=true}` -> {ok, track, track_index, track_created, slot, item, uri, attempts, done, errors, clip} (creates an audio track named `track` when none matches, highlights the slot, same filename lookup + ~2.4 s re-scan as load_sample, `browser.load_item` drops the sample into the highlighted slot; occupied slot -> ok:false unless overwrite),
`meters {ticks=10 (1..100)}` -> {ok, ticks, seconds, is_playing, tracks:[{index,name,peak,silent}], master} (samples track.output_meter_level every ~100 ms, replies once with the peaks; client timeout must cover ticks*100 ms),
`set_arm {track, arm?:bool, monitoring?:"in"|"auto"|"off"}` -> {ok, track, index, done, errors, state:{arm, monitoring}},
`session_record {track, slot=0, bars=4, monitoring?, overwrite?, stop_after?}` -> {ok, track, slot, bars, timed_out, seconds_waited, clip} (arms the track, highlights the slot, `song.trigger_session_record(bars*beats_per_bar)`, polls clip_slot.is_recording, un-arms and replies when the take ends; async reply like load_sample — use a timeout of count-in + bars),
`ping` now also returns is_playing and record_mode; `transport_setup` is implemented (metronome, loop, loop_start, loop_length, swing, tempo, launch_quantization (int or name: bar, quarter, 1/16...), tempo_ramp) as is `clip_edit` (quantize {grid 0..8 or name, amount}, duplicate_loop, crop, loop_start, loop_end, looping, color_index, name).
Every command may carry `ts` (ms since epoch; client.js adds it): commands older than 15 s are answered `{ok:false, error:"stale command dropped"}` instead of firing late. describe_set previews fetch only the first 16 beats of notes (`note_count_partial:true` when the clip is longer). Track/device/param specs match names (exact, then case-insensitive) before being read as indices.
Replies: one JSON line, `{"ok":true,...}` or `{"ok":false,"error":"..."}`.

Live API used: `ControlSurface.schedule_message(1, cb)` (100 ms tick, no threads), `self.song().tempo/tracks/view.selected_track`,
`track.has_midi_input`, `track.clip_slots[i].has_clip/delete_clip()/create_clip(len)/clip/fire()`,
`clip.set_notes(((pitch,start,dur,vel,mute),...))` (fallback `select_all_notes()+replace_selected_notes()`), `clip.name`, `clip.looping`,
`song.create_midi_track(index)`, `Live.Application.get_application().browser.{user_folders,current_project,user_library,samples}`
(walk `.children/.name/.is_loadable/.uri`) and `browser.load_item(item)`. Live's User Library index can be stale for new files, so add the
output folder as a Place (Places > Add Folder...) — `user_folders` is searched first.

Uncertainties: Live 10.1 has `browser.load_item` and `Clip.set_notes`; `Clip.add_new_notes` is Live 11 only (not used).
`set_notes` on an empty clip adds notes in 10.x; if it ever errors we fall back to `replace_selected_notes`. `load_item` targets the
selected track; browser items in User Library show names without `.wav`, so we match both the basename and its stem.
Pattern conversion: start = step*0.25 (+swing*0.5*0.25 on odd steps), duration 0.125, length = bars*4; GM map matches lib/pattern.js.

Live keeps a loaded sample in RAM: Simpler/Sample expose file_path, crop, reverse, warp_as, slices but NO reload API in 10.1, so never reuse a
filename while it is loaded (rotate numbered names). `ClipSlot.fire()` obeys the global launch quantization while playing.
